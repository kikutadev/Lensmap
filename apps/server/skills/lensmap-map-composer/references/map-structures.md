# Structured Map block selection

Use the minimum block capable of preserving the important relationship.

## `definition`

Use for a term or concept whose identity is the main question. Preserve `term`, concise `definition`, optional `keyPoints`, and source references.

## `table`

Use for compact comparison, small quantitative datasets, or exact values where row/column scanning is easier than a graphic.

## `comparison`

Use when a small number of subjects each need grouped qualitative points and card-like columns are clearer than a rectangular table.

## `flow`

Use only when edges matter: causality, processing order, request/data movement, or dependency sequence. Choose `LR` for short horizontal chains and `TB` for longer flows.

## `hierarchy`

Use for parent/child, containment, taxonomy, or decomposition. Do not use it merely because the answer has headings.

## `timeline`

Use when time/order is part of the meaning, not for generic process steps.

## `matrix`

Use when both axes are meaningful categories and cells encode their intersections.

## `chart`

Use only when visual pattern recognition helps. Prefer line for time series, bar for meaningful category magnitude comparison, scatter only for a genuine two-variable relation.

## `callout`

Use as supporting emphasis for a definition, important caveat, note, or warning. Do not make it the primary block when a stronger semantic structure exists.

## `narrative`

Use for concise explanation when no supported structural form improves comprehension. Narrative is valid Map content; it is not a failure to create a visual.
