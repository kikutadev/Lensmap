Lensmap

気になった箇所から、理解の地図をつくる。

Chrome標準PDFビューアをそのまま使い、テキストや図表をReader Workspaceへ集めてExploreします。必要な文脈はWorkspace内の複数PDFから追加探索できます。

はじめ方

  1. PDFをChromeで開くWeb上のPDF、またはファイルURLへのアクセスを許可したローカルPDFを開きます。
  2. 本文を選択して右クリック「LensmapでExplore」は参照を追加して質問欄へ進み、「Lensmapの参照に追加」は現在のWorkspaceへ根拠だけを追加します。
  3. 図・表は「範囲を選択」Side Panelまたは右クリックから、現在見えているPDF画面を固定したCapture Surfaceを開きます。ドラッグしたcrop画像そのものがVisual Sourceとして保存されます。
  4. 質問する同じWorkspaceにある複数PDFのText / Visual Sourceをまとめて質問できます。回答に必要ならWorkspace内検索や節・前後文脈を追加参照します。

Reader Workspace

WorkspaceがExplore、参照、Mapsの所有単位です。Chromeタブを切り替えても会話や下書きは消えません。PDF AとPDF Bの参照を同じWorkspaceへ集めて比較できます。

引用の読み方

S1 / S2… は回答で実際に使ったEvidenceです。Text Sourceは原文、Visual Sourceは保存cropのthumbnailを確認できます。ページが再同定済みならクリックで該当PDFページへ戻れます。

Chrome標準PDFビューアのprivate APIには依存しないため、恒久的な矩形overlayは保証しません。

Visual Source

画像cropが一次情報です。Apple Vision OCRとPDF索引によるページ再同定は検索・preview用の派生情報であり、失敗しても画像Sourceは保持されます。Visual Sourceを質問に使うと、crop画像が画像入力対応Codex modelへ送られます。

AI追加参照

検索hitは候補にすぎません。Codexが実際に本文を読んだ時点でのみS#へ昇格し、追加参照履歴も人間向けの要約として残ります。複数PDFを横断した場合もBook名を保持します。

Maps

完了したExplore回答は自動で1つのMapとして保存されます。同じTurnを再処理しても重複保存しません。Visual Sourceを含むMapは画像を優先して表示し、説明、Evidence、version historyを後から確認できます。

Codex表示

右上では使用model、直近TurnのContext利用状況、Codexの利用枠を確認できます。Visual Sourceを使う場合はimage input対応modelが必要で、非対応modelへOCR-onlyで黙って劣化しません。

表示される利用率

丸いContextゲージ
直近Turnのtoken usageを、そのTurnで報告されたmodel context windowに対する割合として表示します。
利用枠 / 長期利用枠
Codex App Serverが返すrolling rate limitの使用率です。利用枠が複数ある場合はそれぞれ表示します。
LensmapはPDF本文とVisual Sourceをローカルに保持し、Codexには現在のReader Workspaceに必要なEvidenceと限定されたworkspace_* retrievalだけを渡します。
